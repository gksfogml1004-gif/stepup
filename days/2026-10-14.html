🔬 심화 — 더 깊이 보기 (+5분)
① load average의 정체실행 중 + 실행 대기 프로세스 수의 평균(1·5·15분)이에요. 리눅스는 여기에 디스크 I/O를 기다리는 프로세스도 포함해서, CPU는 한가한데 load만 높을 수 있어요. 그럴 땐 top의 wa(iowait)가 높은지 보세요 → 디스크·NFS 지연을 의심.
② 지웠는데 디스크가 안 줄어요프로세스가 열고 있는 파일을 rm으로 지우면 목록에서만 사라지고 공간은 프로세스가 놓을 때까지 그대로예요(10/09 케이스 스터디). 그래서 du 합계와 df 사용량이 크게 다르면 이걸 의심합니다.
# 삭제됐지만 아직 열려 있는 파일
lsof +L1 | head
# 해결: 그 프로세스를 재기동하거나,
# 다음부턴 rm 대신 내용만 비우기
: > app.log
③ 배포판·버전별 차이RHEL/Rocky 7 이상은 ss·systemctl, 오래된 CentOS 6은 netstat·service를 써요. free는 구버전에서 -/+ buffers/cache 줄로, 신버전에서 available 열로 보여줍니다. top 단축키는 공통: P CPU순 · M 메모리순 · 1 코어별 · c 전체 명령어 · q 종료.
④ 리뷰·면접에서 나오는 질문Q. kill과 kill -9의 차이는?
A. kill은 기본으로 SIGTERM(15)을 보내 프로그램이 스스로 정리하고 끝낼 기회를 줘요. kill -9(SIGKILL)은 즉시 강제 종료라 정리 작업 없이 끝나요. 먼저 일반 kill → 잠시 기다린 뒤에도 안 끝나면 -9가 순서입니다.

  • -x는 다른 디스크(마운트)로 넘어가지 않게 해서 결과를 정확하게
  • df -i의 IUse% 100%면 작은 파일이 너무 많은 것 (세션·임시 파일 등)
  • lsof +L1에 큰 파일이 보이면 해당 프로세스가 잡고 있는 삭제 파일
⚠️ 운영 서버에서 find / -name ...처럼 전체를 훑는 명령은 디스크 부하를 줘요. 위처럼 큰 폴더부터 좁혀 가는 방식이 안전합니다.
⚠️흔한 실수현장에서 실제로 자주 나오는 것
  • free 수치만 보고 "메모리 부족" 보고캐시 때문에 free는 원래 작아요. available과 swap 추이를 같이 보고 판단하세요.
  • 로그를 rm으로 지웠는데 용량 그대로프로세스가 열고 있던 파일이에요. lsof +L1로 확인하고, 로그는 : > 파일로 비우는 습관을.
  • 안 끝나는 프로세스에 바로 kill -9정리 작업(임시 파일·연결 종료) 없이 끝나 데이터가 꼬일 수 있어요. 일반 kill → 대기 → 그래도 안 되면 -9.
  • 다른 서버인 줄 모르고 명령 실행운영·검증 서버 창을 여러 개 띄워 두다 생기는 사고예요. 중요한 명령 전엔 hostname·whoami로 확인.

Q1. 코어 4개 서버에서 load average가 7.9, 6.1, 3.4다. 어떤 상태일까?

정답
코어 수보다 높고 1분 값이 가장 커서 부하가 지금 올라가는 중. 범인 프로세스와 iowait를 확인합니다.

Q2. free -h에서 free 300Mi, available 6Gi, swap 사용 0. 메모리가 부족한가?

정답
아니요. 남는 메모리를 캐시로 쓰고 있을 뿐, available이 넉넉하고 swap도 안 써서 정상입니다.

Q3. No space left on device가 나는데 df -h는 40%다. 무엇을 확인할까?

정답
df -i로 inode 고갈(파일 개수 초과)을 확인합니다.

Q4. 로그 50GB를 rm으로 지웠는데 df 사용량이 그대로다. 원인과 해결은?

정답
프로세스가 열고 있던 파일이라 공간이 안 풀린 것. lsof +L1로 확인 후 해당 프로세스를 재기동(또는 다음부터 : >로 비우기).

✍️문제 1쉬움

파일시스템별 디스크 사용량을 사람이 읽기 쉬운 단위로 보여주는 명령은?

정답 2번. df는 파일시스템(파티션) 단위, du는 디렉터리·파일 단위 사용량이에요. -h는 G·M 단위로 보기 쉽게.
✍️문제 2보통

kill PID처럼 시그널을 지정하지 않으면 보내지는 시그널은?

정답 4번. 기본값은 SIGTERM(15), 프로그램에 정상 종료를 요청합니다. SIGKILL(9)은 kill -9로 지정해야 해요.
✍️문제 3함정

ps 명령에 대한 설명으로 틀린 것은?

정답 3번. ps는 실행한 순간의 목록을 한 번만 출력해요. 계속 갱신되는 실시간 화면은 top입니다.

The server started swapping, which slowed down all requests.서버가 스왑을 쓰기 시작하면서 모든 요청이 느려졌다.

좀비 프로세스
📍 top 출력·리눅스 문서
A zombie process remains until its parent collects its exit status.좀비 프로세스는 부모가 종료 상태를 회수할 때까지 남아 있다.
top, free의 열 이름(us, sy, id, wa, avail)은 전부 영어 약어예요. 뜻을 한 번 알아 두면 어느 서버에서든 그대로 읽힙니다.

load average
실행 중·대기 중(리눅스는 디스크 I/O 대기 포함) 프로세스 수의 1·5·15분 평균. 코어 수와 비교해 봄
buff/cache
리눅스가 남는 메모리를 파일 캐시로 쓰는 부분. 필요하면 바로 내어줌
available (가용 메모리)
새 프로그램이 실제로 쓸 수 있는 메모리 추정치. 메모리 부족 판단의 기준
스왑 (Swap)
메모리가 부족할 때 디스크를 메모리처럼 쓰는 공간. 사용이 늘면 전체가 느려짐
inode
파일 하나마다 필요한 정보 공간. 다 쓰면 용량이 남아도 새 파일을 못 만듦 (df -i)
iowait (wa)
CPU가 디스크 입출력을 기다리며 노는 시간 비율. 높으면 디스크·스토리지 지연 의심
RSS
프로세스가 실제 물리 메모리에 올려 쓰고 있는 크기 (ps의 RSS 열)
좀비 프로세스 (Zombie)
이미 끝났지만 부모가 정리하지 않아 목록에 남은 프로세스 (STAT Z)
SIGTERM / SIGKILL
종료 시그널. TERM(15)은 정상 종료 요청(kill 기본값), KILL(9)은 즉시 강제 종료
No space left on device
장치에 남은 공간 없음 — 리눅스·애플리케이션 에러
load average
평균 부하 — top·uptime 출력
high CPU usage
높은 CPU 사용률 — 모니터링 알람·장애 보고
